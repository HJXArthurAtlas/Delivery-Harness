# 校验技能对比：gapfill / planverify / converge / intentverify

四个技能都回答"实现是否对得起意图"，但**所处时机、判断主体、产出物性质**完全不同。它们恰好构成一个 2×2：**事前 / 事后** × **补任务 / 独立判定**。

|  | 事前（implement 前） | 事后（implement 后） |
|---|---|---|
| **追加任务型**（自己判断，写 `tasks.md`） | `che-gapfill` | `che-converge` |
| **独立判定型**（checker 判断，出 verdict） | `che-planverify` | `che-intentverify` |

> 权威行为以各 `skills/<name>/SKILL.md` 为准；本文是分工地图，帮助决定"现在该跑哪一个、结果该信到什么程度"。

## 四技能全表对比

| 维度 | gapfill | planverify | converge | intentverify |
|---|---|---|---|---|
| **核心问题** | 验证任务覆盖全了吗 | **plan 漂移了吗**（动工前审计划） | 代码实现到位了吗 | **diff 越界了吗**（合并前审改动） |
| **输入** | `intent.md` 四节（In scope / Out of scope / Constraints / Failure conditions）+ Acceptance / Edge 场景 + `tasks.md` | `intent.md` + `plan.md` + `tasks.md`（gapfill 后的完整义务集） | intent + plan + tasks + 宪法 + 代码现状 | `intent.md` + `tasks.md` + 完整 git diff |
| **看代码 / diff** | 否 | 否（无代码可看，只有 plan 声明的 surface） | 是（读代码现状，无 git） | 是（只读 diff vs merge-base，不看叙事） |
| **判断主体** | 自己（编排者） | 独立 checker——**固定**为同模型新上下文子代理，无选择、无降级 | 自己（编排者） | 独立 checker——**Tier 阶梯**（跨模型 > 同族弱模型 > 同模型新上下文），`SKC_CHECKER` / `.che/config.local.yml` 本地覆盖可配，派发失败降一档 |
| **编排者的机械层** | 无（直接核对） | **surface 分析**（提议路径 vs in/out-of-scope 分类）+ **确定性 ADR 查询**（共用 `che-adr-check` 的 `check.sh` → `planverify.adr.json`），只收事实不判断 | 无 | **L1** build / test / lint + **L2** 任务完成度 vs diff 证据 |
| **产出物** | 追加 `## Gap-filling tasks` 到 `tasks.md` | **不改任何工件**；写 4 份文件（report + `adr.json` + briefing + checker.txt），统一落特性目录 `evidence/` 子目录 | 追加 `## Phase N: Convergence` 到 `tasks.md` | 不改 `tasks.md`；写 3 份文件（report + briefing + checker.txt），统一落特性目录 `evidence/` 子目录 |
| **判定集** | 无判定（只有 GAP 清单） | PASS / REPLAN_ALLOWED / BLOCKED_DRIFT / BLOCKED_ADR（4 级） | 无判定（findings 按 CRITICAL–LOW 分级） | PASS / REVIEW NEEDED / BLOCKED（3 级） |
| **检查维度** | 约束违反测试、失败条件检查、OOS 回归检查、边界 / 负面测试、横切关注点 | P3a surface 漂移（阻断）、P3b `requested_surface` 裁决（REPLAN 通道）、P3c 义务覆盖、P3d 约束预检、P3e ADR 符合性（阻断） | missing / partial / contradicts / unrequested 四类 gap | L3a OOS（阻断）、L3b 约束、L3c 失败条件覆盖、L3d 场景满足 |
| **ADR / 宪法** | 扫 `docs/patterns/` + `docs/corrections/` 提候选任务 | **唯一直接挂钩 ADR**：governing ADR 全文密封进 briefing，departure = BLOCKED_ADR；`adr_gate` 默认 block | 查宪法 MUST（违反 = CRITICAL，任务排最前） | 把 ADR / corrections 塞进 briefing 供 checker 引用，判定不直接挂钩 |
| **防漂移哲学** | — | "grow inward, not drift outward"：覆盖缺口回 plan 补，越界扩张拒 | `unrequested` 只落任务，不删代码 | OOS 明确匹配即 BLOCKED |
| **新鲜度 / 防作弊** | 无 | **hash 承重**：intent / plan / tasks SHA-256 进报告 frontmatter，`/che-planverify-gate` 拒收过期报告 | 无（每次现场重查） | 机械层当场重跑；密封 briefing 是防火墙 |
| **交互** | 强交互：diff preview + 全收 / 分组 / 逐条 / 全拒，拒高风险项 pushback 一次；收尾按 gate 配置分流——门禁开启（`adr_gate` 默认 block / `planverify_gate` block）问「继续 planverify?」，双 gate off 静态提示直接 implement | 非交互；PASS 收尾单行「下一步：/che-implement」（gate 前置不外显） | 非交互：findings 表 → 直接追加 | 基本非交互（问是否打开报告） |
| **失败语义** | — | **机械层失败 ≠ 判定**：adrkit 挂了直接 stop 不出 verdict；checker 派发失败也无降级、不可编造 | — | 派发失败降一档 Tier，如实记录实际到达的 Tier |
| **下游** | 门禁开启 → 链式问 planverify；双 gate off → `/che-implement`（planverify 降可选） | PASS → `/che-implement`（过 planverify-gate）；REPLAN → 回 `/che-plan`（再生 `tasks.md`）→ **gapfill 重跑** → planverify 重跑 | 再跑 `/che-implement`，之后接 intentverify | PASS → `/che-retro`；BLOCKED → 回 implement 修复后重跑 |

## 容易踩坑的跨技能规则

- **planverify ↔ intentverify 是镜像对**：前者审 plan 声明的 surface（"is the proposed PLAN drifting, before files are edited?"），后者审真实 diff（"did the actual git DIFF drift, after implementation?"）。前者 checker 固定同模型新上下文（无阶梯、失败即停），后者爬独立性阶梯且派发失败可降级。
- **REPLAN 回环必须重跑 gapfill**：`/che-plan` 会再生 `tasks.md`，gapfill 此前的追加会被冲掉。恢复顺序固定为 `/che-plan` → gapfill → planverify；不存在 planverify 直接落回 plan 就完的捷径。
- **planverify 必须在 gapfill 之后运行**：它审的是 plan + gapfill 后 tasks 的**联合义务集**， briefing 里同时密封 plan 全文和 gapfill 后的 tasks 全文；提前运行审的是不完整的义务集，ADR 机械层查的也不是最终 surface。
- **gapfill 追加 tasks.md 但不回写 plan.md 是有意的**：plan 与 tasks 的这类"不同步"由 planverify 的 P3c 联合审查兜住，不是缺陷。
- **四个技能都只追加 / 只报告，绝不代修**：gapfill / converge 把缺口落成任务交回 `/che-implement`；planverify / intentverify 出判定交人决策。intentverify 编排者禁止推翻 checker 的 L3 结论（只能加 meta-note），推翻即破坏独立性声明。
- **planverify 是唯一带确定性机械层的**：ADR 查询走 adrkit 脚本产出可审计 JSON，报告 hash 不匹配即作废——唯一把"校验结果被篡改 / 过期"纳入威胁模型的技能。机械层失败永远不等于 PASS。

## 完整流水线

```mermaid
flowchart LR
    A[intend] --> B[plan] --> B2[analyze<br/>三工件只读体检] --> C[gapfill<br/>补验证任务] --> D[planverify<br/>独立 checker 审 plan]
    D -->|PASS + gate| E[implement]
    D -->|REPLAN / BLOCKED| B
    B -. 再生 tasks.md 后 .-> C
    E --> F[converge<br/>补实现任务] --> E
    F --> G[intentverify<br/>独立 checker 审 diff] -->|PASS| H[retro]
    G -->|BLOCKED| E
```

注意 `D --> B` 与 `B -.-> C` 合起来构成回环：REPLAN / BLOCKED 落回 plan 后，必须沿 plan → gapfill → planverify 完整重走（`/che-plan` 再生 `tasks.md` 会冲掉 gapfill 追加）。

各角色完整顺序、交接门禁与质量环节见 [AI Native 实践指南 §3.2](AI%20Native实践指南.md#32-主线流程)。
