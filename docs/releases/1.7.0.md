# 1.7.0 发版说明（2026-11-11）

## Compound store 记录迁移

- `docs/compound/README.md` 废弃：store 契约不再单独成文，随每特性以 `specs/<task-dir>/compound.md` 沉淀记录承载——头部为精简契约说明，正文 ADRs / Corrections / Patterns / Deferred 四节由 `/che-retro` 在 intentverify PASS 后回填
- `/che-intend` 创建或更新任务目录时确保 `compound.md` 在位（模板单一权威拷贝在 `/che-load`，引用不复制；已有记录绝不覆盖）
- `/che-load` scaffold 只创建 `docs/corrections/`、`docs/patterns/`；会话开场检测到活跃特性目录缺记录时兜底补建
- legacy 清退：`/che-load` 自动删除 `docs/compound/README.md`、把 `docs/compound/_drafts/` 草稿迁往 `specs/<task-dir>/_drafts/`，目录清空后移除；旧 `docs/compound/{adr,corrections,patterns}/` 迁移逻辑不变
- `/che-retro` defer 草稿改存 `specs/<task-dir>/_drafts/`；接受项写入规范位置后按各节格式回填 compound.md 记录

## 本地覆盖层 config.local.yml

- `/che-project-init` 初始化生成 `.che/config.local.yml` 机器本地覆盖层，机器级差异不再污染入库配置
- 覆盖层仅 `language:` / `checker:` 两键可覆盖，其余键回落 `.che/config.yml`（空覆盖层模板随初始化生成）
- 语言规则块同步改为读 `config.local.yml` 优先、`config.yml` 回落的两级解析

## planverify / intentverify 产物归档

- 校验产物归档至 `specs/{slug}/evidence/` 子目录（`intentverify.md`、planverify 报告等随 spec 就近存放）
- CLI `planverify-gate` 与 `/che-retro` 兼容读取新旧两种布局（`evidence/` 优先，旧版平铺文件仍可用）

## 文档与版本

- 实践指南与 README 同步覆盖层口径与发版流程表述
- 版本 bump：根 package.json、omp 插件 marketplace.json、指南版本对齐行 → 1.7.0；`engines.che` 抬为 `>=0.5.0`（evidence/ 布局依赖 CLI 兼容读取）

## CLI 变化

- `@newchiwan/che` 0.4.0 → 0.5.0：gate 配置支持 `.che/config.local.yml` 机器本地覆盖层，且仅 `language`/`checker` 两键可覆盖
- `planverify-gate` 与 retro 产物读取兼容 `specs/{slug}/evidence/` 子目录布局（evidence/ 优先）
