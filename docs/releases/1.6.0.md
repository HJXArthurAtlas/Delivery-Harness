# 1.6.0 发版说明（2026-11-10）

## 交互契约（全技能覆盖）

- 所有需要用户回答的问题一律经交互式提问工具（AskUserQuestion；omp 端即 `ask`）以表单承载，绝不正文输出问题与选项后中断会话等待键入回答；22 个会发问的技能统一在头部挂交互规则块
- clarify 提问循环改为逐题表单：多选题 radio 承载并预选推荐项（推荐理由进表单正文），短答题文本输入预填建议值；自由作答由表单内置自由文本输入承接
- grill / grill-with-docs 问题格式改为每题一个表单（选项 radio + 推荐项预选 + 内置自由文本）；满意度确认门删除「无交互 UI 时正文展示选项等待选择」的纯文本回退
- intend 访谈全链走表单：自由叙述题（goal / why now / 约束 / 场景）经文本或多行文本输入承载，slug 确认改预填文本输入，场景批量评审与 NEEDS CLARIFICATION 批量确认改选项表单
- implement 的 checklist 未全过门禁（原正文 `(yes/no)` 问答）改两选项表单，默认保守暂停；retro 复核问句、gapfill 高风险 pushback、bug 三技能的 slug 歧义 / 覆盖确认 / URL 信任问句、adr-draft 逐条导入、constitution 逐原则确认、git-master 提交询问、project-init 配置逐项提问、PingCode 四技能的选择与确认全部锁定交互工具通道

## 主链收尾顺序修正

- che-implement 完成报告的主流程提示由 `/che-pingcode-sync-status` 修正为 `/che-intentverify`（独立 checker 审判实现 diff）；卡片收尾移至 intentverify PASS 后，避免 BLOCKED 回退时故事卡已单向流转到完成态

## 提交规范

- che-git-master：经 skill pack 流程开发的改动提交页脚另加 `Co-Authored-By: NCW Delivery Harness`；提交时机允许中途逐段或收尾一次补齐（拆分始终按小步规则，提交前过 `npm test`）

- 实践指南与技能交接流程同步交互工具口径与提交规范表述
- 版本 bump：根 package.json、omp 插件 marketplace.json、指南版本对齐行 → 1.6.0
