# diagnose 模式：结构与环境基线核对

诊断对象：已按模板初始化（或疑似初始化过）的项目。原则：**版本钉子的单一事实源是模板仓**；项目自身的 `AGENTS.md`「环境检查」表是随项目固化的基线快照，优先以它为准，不要在本 skill 里复制版本号。

## 1. 结构基线（骨架完整性）

按模板仓 README 第 1 步的骨架清单核对项目根，每项记 存在/缺失：

```
AGENTS.md（由 AGENTS-TEMPLATE.md 改名而来）、.agents/、.specify/、docs/adr/、
scripts/、services/、apps/、Makefile、.gitignore
```

- 缺失项 = 不符合项，只记录，**不要擅自补**（补齐走用户确认）。
- `AGENTS.md` 打开核对章节骨架是否完整：`布局` / `改之前先读什么` / `环境检查` / `pre-push 门禁`；被改写、章节缺失也是不符合项。
- `.agents/skills/` 健康度：应有 speckit-\*（specify init 产出）与团队 skill；列出实际清单，与预期差异记入报告。
- 认知资产在位：根目录 `aoci.txt` / `aoci.meta.txt` / `aoci.code.txt`；被加进 `.gitignore` 视为不符合项。

## 2. 环境基线（工具链）

1. **首选**：读项目根 `AGENTS.md` 的「环境检查」表，逐项按其「检测」列跑命令、按「期望版本」列判定。该表就是本项目固化的基线。
2. **退化**：项目没有 `AGENTS.md`（初始化中途失败等）→ 克隆或在线读取模板仓 `AGENTS-TEMPLATE.md` 的「环境检查」表当基线，**不要凭记忆报版本号**。
3. 全部项目查完再进入汇报，不要边查边装。

## 3. 项目级索引

- codegraph：`codegraph status`；`Not initialized` = 未初始化；已初始化的默认跑一次 `codegraph sync` 刷新（这是检查动作本身，不需确认）。
- AOCI：`aoci --repo . status` 看对齐状态；异常 `aoci doctor`。`.aoci/` 运行时产物只落本机且会增长，属正常，不要清理。

## 4. 汇报与处置规则（与模板巡检纪律一致）

- 全量查完后**一次性汇报**不符合项，逐项问是否按基线表的「安装 / 升级」列处理，经用户确认才执行。
- 确认安装后仍不符 → 排查同名工具多份安装（nvm / vfox / homebrew / install.sh 并存），对 `which` 指向的那份重装。
- 扩展只在缺失或版本不符时补装，正常时不要重装。

## 输出格式

```
# monorepo 结构诊断报告：<项目名>
## 结构：<N> 项不符合
- [缺失/改写] <路径或章节>：<现象>
## 环境：<N> 项不符合
- <工具>：期望 <版本>，实际 <实测>（检测命令 <cmd>）
## 索引：<N> 项不符合
## 建议处置
- <项>：<安装/升级命令，来自基线表>
```
