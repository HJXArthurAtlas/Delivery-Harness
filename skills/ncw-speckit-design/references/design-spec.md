# 设计规约

> 本文件为**设计遵循**，与 `设计自检.md`（设计自检）配套。设计规约写设计规则，不写走查输出；走查每个检查项都要能追溯到本文件规则，没有对应规则的，标记为「待补」，不得直接作为违规判定。
>
> 本规约为**设计向**。上下文不清楚，或规约未覆盖时，向技能使用者确认，不自行补位。
>
> **维护原则**：条目来自真实决策或自检发现。规则应包含规则句和可判定的检查方法；尚无结论的内容标记「待补」。规约变更只改本文件，其他文档只放指针。

# 设计遵循

> 明确不纳入本规约：直接操纵与隐喻拟物、Dynamic Type、Haptics。

## 1. 原则

### P1 一屏一件事

一屏设置一个主动作；次要操作降级为文字链或图标。

**判定**：任一屏存在多个同级主动作，即违规。次要操作未降级为文字链或图标，即违规。

### P2 状态先行

用户第一眼应能判断「现在轮到我做什么」。

**判定**：展示页面截图 3 秒后询问「下一步该做什么」，无法回答，即违规。

### P3 数据可信

数据拿不到时显示 `--`，不得显示 `0` 代替缺失值。状态展示必须有可追溯的数据依据。

**判定**：

- 对照数据来源逐字段检查 `null`、缺失值和 `0` 的显示；
- 检查状态标签能否追溯到实际字段或已确认的字段映射；
- 检查数据缺失时界面是否仍能正确表达状态。

### P4 拇指可达

主动作位于拇指热区，即屏幕下半部；交互目标不小于 `44×44pt`；对比度不低于 `4.5:1`。破坏性动作不得位于热区中心。滑动操作使用行程与阻尼。

**判定**：

- 检查主动作是否位于拇指热区；
- 测量交互目标尺寸及对比度；
- 检查破坏性动作是否位于热区中心；
- 检查滑动操作是否具有明确行程和阻尼。

> **待补**：拇指热区的具体测量方法、对比度的测量对象及特殊状态适用范围，需补充统一口径。

### P5 说用户的话

面向用户的文案使用用户熟悉的表达，例如「现在能办吗」「要多少钱」「什么时候能好」，避免使用技术术语。

**判定**：面向用户的文案出现「参数」「异常」「加载失败」「字段」等技术表达时，检查是否有用户可理解的替代说法。

### P6 一致即正确

同一动作、同一状态，在全产品中使用一致的文案和视觉样式。

**判定**：同一场景、同一含义的动作使用不同名称或样式时，视为不一致。不同业务含义的动作不得仅为追求统一而强行使用同一词语。

### P7 上下文可寻

用户应能理解当前所处位置、返回路径，以及当前还剩什么。多步流程必须提供进度指示。

**判定**：

- 对适用页面截图 3 秒，用户无法回答「我在哪、如何返回、还剩什么」，即违规；
- 多步流程没有进度指示，即违规。

## 2. 模式

### 2.1 空态与无权限状态

**适用状态**：

- **无数据**：当前没有可展示的数据；
- **无结果**：存在数据，但当前条件下没有匹配结果；
- **无权限**：用户没有查看或操作权限。

无网络、请求失败等属于异常或反馈状态，不应仅因页面上没有内容就归为上述空态。

**应当做到**：

- 说明当前为什么没有内容；
- 说明用户可以做什么，或下一步如何处理；
- 面向用户的文案符合 P5；
- 不同成因的状态表达应能区分。

**避免**：

- 只放插画，不提供说明或可行操作；
- 无数据、无结果、无权限三种状态不加区分地共用同一表达。

### 2.2 动作文案

**应当做到**：

- 同一动作遵循 P6，使用统一词语；
- 按钮使用清晰的动词短语，避免只写「确定」「取消」；
- 破坏性动作直接说明动作对象，例如「删除」「退出」。

**动词选择**：根据操作者、操作对象和操作是否可逆，选择明确的动作词。

**待收敛词**：本业务内尚未收敛的同义动作词。词义和适用场景尚未收敛前，不得自行统一或替换。

### 2.3 确认与防错

**应当做到**：

- 破坏性操作应有与风险相称的防误操作机制；
- 需要确认时，说明操作后果，不只问「确认吗」；
- 输入错误应尽可能在提交前拦截；
- 可安全撤销的操作优先考虑撤销或恢复能力；
- 弹窗用于防止误操作，不用弹窗替代本可提供的撤销能力。

**避免**：

- 高频操作无必要地增加确认步骤；
- 只提示错误，不说明如何处理；
- 操作可安全撤销时，仅为防后悔而用弹窗拦截。

> **待补**：哪些破坏性操作必须二次确认、哪些可用撤销替代、撤销时限及恢复列表范围，需要根据真实业务决策补充。未确认前，不得仅凭本条推断具体交互方案。

### 2.4 打断与恢复

**适用场景**：可能被电话、导航、锁屏、场站作业等情况打断的操作。

**应当做到**：

- 用户返回后尽可能恢复到离开时的位置和状态；
- 草稿自动保留；
- 长流程支持中断后继续办理。

**避免**：

- 打断后无故要求用户从头开始；
- 用户已输入的内容静默丢失。

**判定示例**：

- 表单页切到后台 5 分钟后返回，已填写内容仍在；
- 上传中断后支持续传，避免不必要的重复上传。

### 2.5 模态节制

弹窗用于「不处理就不能继续」的阻断决策。

**应当做到**：非阻断信息使用横幅、内联提示或底部浮层等适当形式。

**避免**：

- 用弹窗展示通知或成功提示；
- 同一页面同时出现多个弹窗；
- 将非阻断信息设计为阻断流程。

**判定**：若信息不处理也能继续完成当前流程，应评估是否可以不用弹窗。

## 3. 基元与视觉取值

### 3.1 动效即信息

转场方向应与层级方向一致：进入详情时推进，返回时退出。动效时长收敛到 2～3 档；禁止使用装饰性动效。

**待补**：动效时长的具体取值与适用范围尚未定义，以后续确认结果为准。

---

## 4. 规则争议与维护

1. **规则争议**：向技能使用者确认，不自行推断。
2. **发现规则缺口**：先在走查记录中标记「待补」，并说明具体场景和影响。
3. **规则更新**：基于真实决策或自检发现，经确认后更新本文件；设计自检对应检查项同步标注新的规则来源。
4. **具体问题与规则缺口分开处理**：修复某个页面问题，不代表自动新增一条通用规则；只有确认其具有通用性后，才回流至设计规约。
