# Load Compound Store

You load the project's settled decisions and the committed compound store, and inject them into the current session's agent context. Settled ADRs come from the adrkit corpus at `docs/adr/` (override with `ADRKIT_DIR`); past mistakes and approved patterns come from `docs/corrections/` and `docs/patterns/`. All of them should constrain everything the agent does for the rest of the session.

---

## What to do

**1. Detect or create the compound store, and backfill the feature record.**

If any part of the scaffold is missing, create the missing directories:

```
docs/
├── corrections/      (empty)
└── patterns/         (empty)
```

The store has no standalone README: its contract travels with each feature as a per-feature record at `{FEATURE_DIR}/compound.md`. When `che paths --json` resolves an existing `FEATURE_DIR` (the task directory `specs/NNN-{slug}/`) and `compound.md` is missing there, write the record skeleton into it with the directory name filled in. This skeleton is the single canonical copy — `/che-intend` and `/che-retro` reference it; port all changes together:

```markdown
# Compound Record — {NNN-slug}

Per-feature record of what this feature contributed to the compound store. Store contract: settled ADRs live in the adrkit corpus at `docs/adr/` (ids allocated by the adrkit scaffold, each carries a **Rule for AI** line); corrections live in `docs/corrections/` (`YYYY-MM-DD-slug.md`, auto-captured on user pushback, reviewed at retro); approved patterns live in `docs/patterns/` (`slug.md`, explicit user approval at retro). `/che-retro` fills the sections below after intentverify PASS; this file is metadata only — it never replaces the canonical artifacts.

## ADRs
<!-- /che-retro: `- ADR-NNN {title} — Rule for AI: {one-liner}` per ADR allocated from this feature -->

## Corrections
<!-- /che-retro: `- {YYYY-MM-DD-slug}: {derived rule}` per correction captured or reviewed -->

## Patterns
<!-- /che-retro: `- {slug}: {when to use, one line}` per approved pattern -->

## Deferred
<!-- /che-retro: `- {filename}: {why deferred}` per draft parked in `_drafts/` -->
```

Never overwrite an existing record.

When initializing a new store, tell the user: *"Compound store initialized: corrections at `docs/corrections/` and patterns at `docs/patterns/`. Per-feature contribution records live at `specs/<task-dir>/compound.md`, filled by `/che-retro`. Empty for now — it will fill over the next few features."*

**2. Migrate legacy artifacts, then read all files.** Migrate a legacy `docs/compound/adr/` corpus into the canonical adrkit corpus with the legacy-corpus instructions in `/che-adr-draft`. Move any legacy `docs/compound/corrections/` and `docs/compound/patterns/` files to `docs/corrections/` and `docs/patterns/`. Retire the legacy `docs/compound/` metadata dir: delete `docs/compound/README.md` (superseded by the per-feature records) and move any `docs/compound/_drafts/` files into `specs/<task-dir>/_drafts/` — when the owning spec is not identifiable (no session-bound feature and no unambiguous slug match), leave those files in place and list them for the user; remove `docs/compound/` itself only once it is empty. Then read all files in the adrkit corpus (`docs/adr/`, or `$ADRKIT_DIR` when the project overrides it) and in `docs/corrections/` and `docs/patterns/`. Also read `docs/architecture.md` (the project's architecture profile, generated by `/che-project-init` for existing-code repositories) when it exists; when it is missing, note that once in the confirmation in step 4 — do not scaffold it, `/che-project-init` owns that artifact.

**3. Inject a context summary** at the start of the agent's working memory:

```
COMPOUND STORE LOADED

ADRs (settled decisions, do not re-debate):
- ADR-001 {title} — Rule for AI: {one-liner}
- ADR-002 {title} — Rule for AI: {one-liner}
...

Corrections (past mistakes, do not repeat):
- {date}-{slug}: {derived rule}
...

Patterns (approved approaches, reach for these by default):
- {slug}: {one-line description, when to use}
...

Architecture profile (docs/architecture.md, project structure — place things where it says):
- Backends: {service} ({stack}, :{port}) — {one-line purpose}
- Frontends: {app} ({stack}) — {one-line purpose}
- Shared libs: {lib} — used by {...}
- Infra containers: {middleware} ({image/version}, :{port}) — used by {...}
- Runtime calls (human-confirmed): {caller -> callee (protocol)}
...
```

**4. Confirm to user**:

*"Loaded: {N} ADRs from the adrkit corpus, {N} corrections and {N} patterns from the compound store{profile_note}. Settled decisions will be respected; known corrections will be avoided; patterns will be reached for during the rest of this session."* — where `{profile_note}` is `", and the architecture profile (docs/architecture.md)"` when the profile exists, or `"; no architecture profile yet — /che-project-init can generate one (existing-code repositories only)"` when missing.

---

## Notes for the rest of the session

After loading, when the agent makes design decisions during `/che-intend`, `/che-implement`, `/che-intentverify`, etc., it should:

- **Reference relevant ADRs** when constraints are being chosen — don't propose a constraint that contradicts a settled ADR
- **Avoid known correction patterns** — if the agent is about to do something that matches a correction note, stop and warn
- **Reach for established patterns** by default rather than inventing fresh approaches

---

## Re-loading after context compaction

If the session's context is compacted by the harness, the compound store summary may be dropped. The user can re-run `/che-load` to restore it.

---

## Tool choices

- **Read** for scanning compound store files
- **Bash** (`mkdir`, `ls`, `cp`, `mv`) for scaffold creation and the explicit legacy migrations above
- **Write** for the backfilled `{FEATURE_DIR}/compound.md` record and missing scaffold directories

---

## Bundled references

- `references/ref.md` — conceptual reference for the whole compound workflow (ICE slots, why compartmentation defeats reward-hacking, planverify vs intentverify). Read it when the user asks *why* the workflow is designed this way; it is background, not a procedure.

---

## What you do NOT do

- **Edit compound store content during load** — scaffolding, the `{FEATURE_DIR}/compound.md` record backfill in step 1, and the explicit legacy migrations above are the only exceptions; new learnings are written via `/che-retro`.
- **Re-load mid-session unsolicited** — load happens at the start of a feature; only re-run if the user explicitly invokes it after context compaction.
- **Block the rest of the session if the store is empty** — empty store is normal on a fresh project; just confirm scaffold and continue.
